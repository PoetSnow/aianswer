# 智学数学 MVP 产品交互规则

## 0. 主流程（权威）

```text
选择题
  ├─ 答错 → 分步引导 → 再尝试 → 解析 → 掌握？
  └─ 答对 → 变式验证
              ├─ 答对 → 解析 → 掌握？
              └─ 答错 → 分步引导 → …
```

| Mode | 含义 |
|------|------|
| `ANSWERING` | 原题 A–D |
| `VARIANT` | 变式选择题（题库 `variant`） |
| `GUIDING` | `guideSteps` 短答引导 |
| `COMPLETED` | 解析后询问是否掌握 |

- 原题 / 变式选择题对错：**程序**（选项字母）
- 引导轮对错与是否推进：**LLM 结构化判断**（`assessment` / `shouldAdvance` / `shouldComplete` / `shouldReveal` / `message`）；程序只读字段并钳制；JSON 解析失败或未配置 LLM 时才用 `expectedAnswers` + 正则兜底
- 引导话术：题库 `guideSteps.ask` 定**教学意图**；开场润色与每轮 `message` 均由 LLM 产出
- 掌握？→「我掌握了」下一题 /「还不太懂」再进引导

---

## 1. MVP 核心目标

验证一个核心假设：

> 学生做错题后，不直接展示答案，而是通过有限轮次的 AI 启发式引导，让学生自己完成解题。

同时：

> 学生答对后，也必须给出简洁的解析，让学生知道为什么是这个答案。

本 MVP 不追求完整的数学教育系统，只验证“答题 → 判断 → 解析 / 引导 → 完成”的核心体验。

---

# 2. 核心流程

```text
开始做题
   ↓
学生提交答案
   ↓
判断是否正确
   ├── 正确
   │    ↓
   │  展示正确结果
   │    ↓
   │  展示解析
   │    ↓
   │  完成
   │
   └── 错误
        ↓
      进入 AI 引导
        ↓
      学生再次尝试
        ↓
      判断是否正确
        ├── 正确 → 展示解析 → 完成
        │
        └── 错误 / 不理解
                  ↓
              下一层提示
                  ↓
             最多 2～3 轮
                  ↓
          展示完整解析 / 答案
```

---

# 3. 正确答案流程

学生第一次回答正确时：

```text
正确
↓
展示“回答正确”
↓
展示解析
↓
结束本题
```

例如：

> ✅ 回答正确！
>
> `2x + 3 = 11`
>
> 两边同时减去 3：
>
> `2x = 8`
>
> 两边同时除以 2：
>
> `x = 4`
>
> 所以答案是 **B**。
>
> 你先移除常数项，再求 x，这个思路是正确的。

### 要求

正确解析：

* 必须解释为什么答案正确
* 不需要制造额外对话
* 不需要继续提问学生
* 解析应当简洁
* 对选择题，可以解释关键解题步骤
* 不要求 LLM 进行复杂教学

---

# 4. 错误答案流程

学生回答错误：

```text
学生答错
↓
不直接展示正确答案
↓
进入引导模式
```

第一次提示的目标：

> 指出思考方向，但不要直接给答案。

例如：

> ❌ 这次没有选对。
>
> 我们先别急着看答案。
>
> 题目是：
>
> `2x + 3 = 11`
>
> 如果我们想让 `x` 单独留下，应该先处理左边的哪一部分？

---

# 5. 学生表示“不懂”

以下表达统一视为：

```text
CONFUSED
```

例如：

* 不懂
* 我不太懂
* 不会
* 还是不会
* 没明白
* 看不懂
* 不知道
* 还是不理解

MVP 不需要区分这些表达之间的细微语义差异。

产品层统一处理：

```text
学生状态 = CONFUSED
```

然后进入下一层提示。

---

# 6. 提示层级

MVP 只需要 3 个提示等级。

## Hint Level 1：方向提示

目标：

> 帮助学生找到应该思考的位置。

例如：

> 想一想，我们的目标是让 `x` 单独留下。
>
> 现在 `x` 的旁边还有一个 `+3`，你觉得应该先处理什么？

不能直接给出：

> 两边减 3。

---

## Hint Level 2：步骤提示

学生仍然错误或表示不理解。

目标：

> 明确告诉学生当前应该进行什么类型的操作，但尽量让学生完成最后一步。

例如：

> `+3` 是我们现在需要消掉的部分。
>
> 加法的相反运算是什么？
>
> 如果要消掉 `+3`，你觉得应该两边都加 3，还是两边都减 3？

---

## Hint Level 3：具体操作

学生连续错误或仍然无法理解。

此时可以明显降低难度。

例如：

> 我们直接做这一步：
>
> 两边同时减去 3：
>
> `2x + 3 - 3 = 11 - 3`
>
> 所以：
>
> `2x = 8`
>
> 现在最后一步交给你：
>
> `x = ?`

此时仍然尽量让学生完成最后一步。

---

# 7. 最大引导次数

MVP 默认：

```text
最多 3 次提示
```

如果学生在 3 次提示后仍然没有答对：

```text
停止继续引导
↓
展示完整解析
↓
展示正确答案
↓
本题结束
```

目的：

> 避免 AI 无限循环，也避免学生一直输入“不懂”。

---

# 8. 正确答案后的处理

无论学生是：

```text
第一次答对
```

还是：

```text
经过提示后答对
```

最终都进入：

```text
正确
↓
解析
↓
完成
```

例如：

> 🎉 做对了！
>
> ### 解析
>
> 原方程：
>
> `2x + 3 = 11`
>
> 第一步，两边同时减去 3：
>
> `2x = 8`
>
> 第二步，两边同时除以 2：
>
> `x = 4`
>
> 所以答案是 **B**。

如果学生经过提示后答对，可以增加一句：

> 你刚才通过两步提示找到了正确思路。

但不要过度表扬或生成长篇总结。

---

# 9. LLM 的职责

LLM 不负责决定整个产品流程。

产品代码负责：

```text
是否正确
提示次数
当前 Hint Level
是否结束
是否展示答案
```

LLM 负责：

```text
根据当前教学状态生成自然语言提示
```

输入给 LLM 的核心上下文：

```text
题目
选项
正确答案
学生答案
当前提示等级
之前已经给出的提示
学生最新输入
```

例如：

```text
question:
2x + 3 = 11

student_answer:
A

correct_answer:
B

hint_level:
2

student_message:
我不懂
```

要求 LLM：

```text
1. 根据当前 hint_level 给出对应层级的提示
2. 不重复之前完全相同的提示
3. 不超过当前提示等级允许的信息量
4. 如果是正确答案，不进入引导，直接生成解析
5. 如果学生表示“不懂”，视为 CONFUSED
6. 保持简短，一次只解决一个步骤
```

# 10. 产品状态

MVP 最少维护以下状态：

```text
Question
StudentAnswer
IsCorrect
HintLevel
AttemptCount
StudentState
PreviousHints
Completed
```

其中：

```text
StudentState:

CORRECT
WRONG
CONFUSED
```

MVP 暂时不需要设计更多学生心理状态。

# 11. 一个完整示例

```text
对，我们需要先处理 +3。

减法

系统：
对！

2x = 8

现在最后一步：

学生：
4

系统：

解析：
...
```

## 场景 C：答错 → “我不懂” → “还是不懂”

```text
学生：
A

系统：
❌ 这次没有选对。

想一想，如果要让 x 单独留下，
应该先处理哪一部分？

学生：
我不懂

系统：
没关系，我们换个更简单的问题。

如果：
x + 3 = 8

你觉得应该加 3 还是减 3？

学生：
不懂

系统：
我们直接看一个具体步骤：

x + 3 - 3 = 8 - 3

所以：

x = 5

回到刚才的题目，
我们也需要先把 +3 消掉。

现在你试一下：

11 - 3 = ?

8
```

继续完成后续步骤。

# 12. MVP 暂时不做

以下功能不属于当前 MVP：

* 用户长期学习档案
* 知识点画像
* 知识图谱
* 个性化课程
* 长期记忆
* 多 Agent
* RAG
* 自动生成课程
* 复杂 Workflow
* 学习能力评分
* 错题本体系
* 大规模题库推荐

这些属于后续产品化方向。

---

# 13. MVP 验证指标

当前 MVP 重点观察：

### 指标 1：错误后是否继续尝试

学生答错后：

> 是否愿意继续回答，而不是直接看答案。

### 指标 2：提示是否真的降低难度

连续说“不懂”时：

> AI 是否能够逐步降低问题难度。

### 指标 3：提示次数是否足够

观察：

> 大多数题目在 1～3 次提示内，学生能否自己完成。

### 指标 4：正确后的解析是否有价值

观察：

> 学生答对以后，解析是否能够让学生理解“为什么”。

---

# 14. MVP 最终定位

不是：

> AI 数学聊天机器人

而是：

> **一个“答错后不给答案，而是通过有限次启发帮助学生自己做出来”的数学答题产品。**

核心体验：

```text
答对
→ 解析

答错
→ 提示
→ 再尝试
→ 提示
→ 再尝试
→ 答对
→ 解析

或者：

答错
→ 提示
→ 不懂
→ 降低难度
→ 再尝试
→ 最终解析
```

这就是当前 MVP 应该验证的完整产品闭环。
